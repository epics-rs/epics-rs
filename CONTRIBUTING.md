# Contributing to epics-rs

Thanks for your interest! This is a dense codebase — a behavioral port of
EPICS Base, CA, and PVA — so this guide covers the things that are not
obvious from a fresh clone.

## Quick start

```bash
git clone https://github.com/epics-rs/epics-rs
cd epics-rs
cargo build --workspace        # rustup picks the pinned toolchain
cargo nextest run --workspace  # or: cargo test --workspace
```

The toolchain is pinned by `rust-toolchain.toml` (currently 1.94.0,
edition 2024) — rustup installs it automatically. No EPICS C installation
is needed for the default build and test run.

## Before you push

CI enforces, in this order — run the same commands locally:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo test --doc --workspace     # nextest does not run doctests
```

Warnings are errors. Please fix at the source rather than adding
`#[allow(...)]`.

## Tests that need a C EPICS installation

Tests marked `#[ignore]` (mostly `interop`/`tls_interop`/`stability` in
`epics-pva-rs`, and the oracle harness) drive the **compiled C tools**
(`softIoc`, `caget`, `pvxget`, ...) against the Rust implementation. They
are skipped by default, so a plain `cargo nextest run` never needs EPICS
installed.

To run them, build [EPICS Base](https://github.com/epics-base/epics-base)
(and [pvxs](https://github.com/epics-base/pvxs) for PVA tests), put their
`bin/<host-arch>` on `PATH`, and run:

```bash
cargo nextest run --workspace --run-ignored all
```

The **differential oracle** (`crates/epics-oracle-rs`) boots the C
`softIoc` and the Rust IOC on the same `.db`, drives both with identical
CA operations, and diffs what a client can observe:

```bash
cargo run -p epics-oracle-rs --bin oracle -- --help
```

CI runs these in the gated `interop.yml` workflow.

## Generated code — do not hand-edit

Files marked `@generated by tools/dbd-codegen` are derived from the
vendored `.dbd` files. Edit the `.dbd` (or the generator), then:

```bash
cargo run -p dbd-codegen -- --write   # regenerate
cargo run -p dbd-codegen -- --check   # what CI runs; drift is a failing test
```

## Porting rules

This is a *behavioral port*: client-observable behavior follows upstream
EPICS Base / pvxs unless a deviation is documented.

- For a behavioral change, cite the upstream C/C++ source
  (`file.c:line`) in the commit message or a comment.
- If you believe upstream itself has a bug, do not silently "fix" it in
  the port — open an issue so the deviation is recorded (see
  `docs/upstream-c-bugs` for prior art).
- `archaeology/` preserves the porting review record; it is historical
  data, not build input — no need to update it in a PR.

## Commit messages

`type(scope): imperative summary` — e.g. `fix(pva): ...`,
`doc(rtems): ...`, `test(oracle): ...`. Look at `git log` and match.
